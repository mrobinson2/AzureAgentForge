# v1.7.0 Release Plan — 2026-07-11 (ships this weekend)

v1.7 is the biggest AzureAgentForge release to date. The draft release already carries four
merged features (sweep performance hardening, inspector summary, memory digest, escalation
SLA auditor). This plan adds the week's best portable work as first-class, sanitized,
public-ready content, plus a full docs/release refresh. Coordinator integrates; each
package is an isolated worktree with exclusive file ownership.

## Sanitization rules (every package, non-negotiable)
Public repo. No MRTek tenant data, customer names, real phone numbers, keys, or internal
hostnames; all example data fictional and labeled; feature flags default OFF; do not touch
deploy.yml (stays uncommitted by policy); branch from `main` (remote `public`); nothing in
examples requires a live Azure subscription to read or test locally.

## Work packages

### P1 — `examples/governed-ui-patterns/` (port of the Governed-AI pattern library)
Nine themeable UI governance patterns (honesty badge, trust receipt, refusal card,
approval gate, pricing-policy engine, autonomy panel, sealed record, movement log, signed
charter) + the 11-check conformance linter (`check.js`) + a live demo page + README
explaining the composition rules. Rewrite copy to be vendor-neutral (no MRTek business
names); keep the linter's exit-code contract and document it as CI-able. Tests: linter
runs clean on the shipped demo page; `node --check` on all JS.

### P2 — `samples/foundry-chat-proxy/` (minimal AI Foundry chat backend)
The minimal Azure Function chat proxy pattern: Node 24 Flex Consumption function fronting
an AI Foundry chat deployment with a grounded persona, message clamping, and
prompt-injection guardrails; Bicep for the function app; runbook README including the
hard-won gotchas (classic Y1 Linux has no Node 24 image — host never starts; OneDeploy
415 on Flex → use config-zip; secrets are named operator gates). Generic persona (a
fictional "Fabrikam Plumbing" grounding block, labeled). Tests: `node --check`; bicep
compiles if CLI available (else documented).

### P3 — `examples/governed-transaction-saga/` (event-sourced governance core)
A compact (~300-line + tests) sanitized distillation of the governed-transaction pattern:
append-only event log with tenant/correlation/causation IDs and idempotency; a fold/apply
state machine for a service transaction; complete-at-write receipts; an audit walk that
produces a chronological narrative plus a receipt-gap report. Pure Python stdlib, pytest
suite, README tying it to the platform's HITL approval + governor features. All-new code
written for the example (not a copy of any private repo file), fictional scenario.

### P4 — Docs & release package: README.md, ROADMAP.md, release notes
- README: feature overview refreshed to include the four draft-release features, the
  security remediation batch (#97, once merged), and the three new example/sample packages;
  quickstart verified against current repo layout.
- ROADMAP: mark shipped items; set post-1.7 horizon (adapter maturity, second vertical
  example, prompt-governance loop methodology doc).
- `docs/releases/v1.7.0.md`: full release notes — the biggest-release framing earned by
  enumeration, grouped (Platform features / Security / Governance examples / Docs), with
  upgrade notes and honest flags-off defaults. The GitHub draft release body gets this
  text (update draft only — PUBLISHING is Michael's weekend action).
