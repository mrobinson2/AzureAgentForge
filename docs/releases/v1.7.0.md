# v1.7.0 — release notes

> **Technical reference for contributors.** For the operational overview, start at [README](../../README.md) or [Architecture](../architecture.md).

v1.7 is the milestone that brings together security, governance, memory,
deployment, validation, observability, cost-control, and agent-loop reliability.
This document is the consolidated technical history of that milestone, enumerated
the only way that is checkable: by the substantive, independent things it ships.
Four governor features found and fixed against a real corpus, a
security-remediation batch spanning ~27 findings across seven subsystems, three
new self-contained example/sample packages, a full docs refresh, and a
reliability-hardening batch (below) that turns several silent failure modes loud
— grouped in the sections that follow.

Every runtime addition ships with its feature flag seeded **off**. Applying this
release to a running system changes nothing until you turn a flag on and apply
the listed migrations. The default deploy footprint is unchanged.

## Platform features (governor)

Production feedback folded back into the Memory Governor: one performance fix
and three read-only operator-visibility endpoints. All are additive; the three
ship-dark features leave the daily `/digest` post byte-for-byte unchanged while
their flags are off.

1. **Contradiction sweep performance hardening.** The sweep's candidate query
   (`services/memory-governor/src/governor/contradiction.py`) is a `pg_trgm`
   similarity self-join on `documents` — O(n²) pairs. With no trigram index even
   ~1k eligible docs (~500k pairs) blew through the pool-wide 30s command
   timeout, so every pass raised `TimeoutError` and no pair was ever judged
   (found in production upstream). Migration
   `infrastructure/migrations/0009_contradiction_sweep_perf.sql` adds a
   `gin (content gin_trgm_ops)` index on `documents.content`, guarded on
   `pg_trgm` extension presence (managed-Postgres allow-list), with an honest
   built-vs-skipped audit canary. Two new knobs bound the fetch:
   `CONTRADICTION_QUERY_TIMEOUT_S` (default 300s) is a dedicated timeout for the
   candidate fetch only, and `CONTRADICTION_LOOKBACK_DAYS` (default 30; `<= 0`
   disables) bounds steady-state passes to pairs involving a recent doc.
   Regression tests pin the bounds.

2. **Read-only memory inspector summary.**
   `GET /memory/inspector-summary?workspace_name=…` (`X-Governor-Key`) returns a
   workspace-scoped aggregate for operator inspection: live counts by memory
   class, verification state, and source type (deleted rows excluded); the
   embedding-sync queue depth and last sync; and a 7-day tally of Plane C ranking
   modes (`vector` / `trigram` / `trigram_fallback`). No mutation, no new state
   — same auth as the rest of the `/memory/*` surface
   (`services/memory-governor/src/governor/main.py`).

3. **Daily memory review-queue digest (ship-dark).** `GET /memory-digest`
   (`services/memory-governor/src/governor/memory_digest.py`) is a per-workspace,
   read-only worklist of what needs operator action: pending pin-candidates,
   memories the contradiction sweep flagged `needs_review` (with the sweep's
   suggested resolution from the review note), and `task_scoped` memories
   expiring within 7 days. Every section is capped (default 10) with an honest
   "+N more" overflow line, and the raw fetch is bounded (`MEMORY_DIGEST_FETCH_CAP`)
   so a pathological backlog never loads unbounded rows. Always available for
   preview; `MEMORY_DIGEST_ENABLED` (seeded **off**, migration
   `infrastructure/migrations/0010_memory_digest_flag.sql`) only gates folding the
   listing into the daily `/digest` post — flag off leaves `/digest` byte-for-byte
   unchanged.

4. **Escalation SLA auditor (ship-dark).** `GET /escalation-sla`
   (`services/memory-governor/src/governor/escalation_sla.py`) measures the human
   side of the autonomy handoff. An event taxonomy
   (`escalation_opened` / `escalation_acked` / `escalation_resolved`) on the
   existing `agent_events` spine, correlated by `payload.escalation_id`, plus a
   pure pairing/rollup that measures human ack latency against a per-tenant SLA
   (default 30m, optional business-hours clock; malformed config degrades to the
   default with a warning rather than crashing). TTL expiry always counts as a
   breach and as unresolved — the approval gate's fail-closed posture is made
   visible, never weakened. The v1.5 approval seam's `autonomy_decision` events
   serve as retroactive ack+resolution, so historical holds become auditable the
   moment emitters exist. Read-only throughout: the auditor never approves,
   extends, or re-routes. No new tables — migration
   `infrastructure/migrations/0011_escalation_sla_flag.sql` is a flag seed only;
   `ESCALATION_SLA_ENABLED` (seeded **off**) only gates the `/digest` fold-in.
   Event emitters land when the HITL approval seam (`apps/paperclip/approval.mjs`)
   is wired for real volume; until then the pipeline is offline-tested and reports
   an honest zero.

**Tests:** 205 memory-governor tests (52 new across these four features);
CI green on PRs #100, #101, #102.

## Security

5. **Security remediation batch (PR #97).** A batch of ~27 findings (aaf-0001
   through aaf-0027) remediated across the auth-proxy, the multi-tenant reference
   design, model-router, chat bridges, memory-governor, the installer /
   forge-console, and the infrastructure modules. This is the headline of the
   v1.7 security posture. The batch groups as:
   - **Fail-closed auth.** model-router, memory-governor, slack-bridge,
     teams-bridge, and the multi-tenant control-plane / memory-store now refuse
     to serve (`503`) when their auth secret is unconfigured, instead of silently
     running open.
   - **Tenant isolation.** memory-store derives `tenant_id` from a verified
     bearer token (never client-supplied path/body); Postgres RLS backstops both
     the control-plane and memory-store tables; the tenant-console `vertical`
     field is strictly allowlisted + realpath-contained to close a
     path-traversal route.
   - **CSRF / DNS-rebinding.** auth-proxy, installer, and tenant-console treat a
     missing `Origin` as a failed check on state-changing requests, and add
     `TrustedHostMiddleware` to the loopback-only consoles.
   - **Prompt-injection fencing.** untrusted inbound text (Slack/Teams messages,
     governed-memory content, watchdog-captured agent error text) is wrapped in
     explicit untrusted-data delimiters before it reaches a model or another
     agent's context.
   - **Error-detail hardening.** model-router and control-plane no longer echo
     raw upstream/DB exception text to callers; memory-governor projects an
     explicit column list instead of `SELECT *`.
   - **Secure-by-default infra.** Key Vault and storage-account firewalls default
     to `Deny` with explicit allowlist variables; Postgres gains audit/TLS server
     parameters; `honcho_workspace_name` has no default so environments cannot
     silently share a governed-memory workspace; `docker-compose.yml` pins image
     tags instead of floating `:latest`.
   - **Installer hardening.** scaffold CLI params are allowlist-validated before
     becoming argv (argument-smuggling), and the session-token URL is withheld
     from logs when the browser auto-open succeeds.

   Every route touched is either the sanitized public reference design
   (`experimental/multi-tenant/`, not wired into the runnable stack) or an
   in-repo service/tool. No infrastructure was applied and no secrets are
   included. Offline test evidence: auth-proxy 43/43, installer 83/83,
   slack-bridge 23/23, teams-bridge 21/21, watchdog 75/75, model-router 195/195,
   memory-governor 153/153, tenant-console 9 passed/1 skipped;
   `terraform fmt/validate` clean; `scripts/scan-internal-refs.sh` clean.

## Governance examples & samples

Three new self-contained packages land in this release cycle as their own PRs.
Each is sanitized (fictional example data, labeled), flags-off by default, and
readable/testable locally with no live Azure subscription.

6. **`examples/governed-ui-patterns/`** — a port of the Governed-AI pattern
   library: nine themeable UI governance patterns (honesty badge, trust receipt,
   refusal card, approval gate, pricing-policy engine, autonomy panel, sealed
   record, movement log, signed charter), an 11-check conformance linter
   (`check.js`) with a documented CI-able exit-code contract, a live demo page,
   and a README covering the composition rules. Copy is vendor-neutral. Tests:
   the linter runs clean on the shipped demo page; `node --check` on all JS.

7. **`samples/foundry-chat-proxy/`** — the minimal AI Foundry chat backend
   pattern: a Node 24 Flex Consumption Azure Function fronting an AI Foundry chat
   deployment with a grounded persona (a fictional "Fabrikam Plumbing" grounding
   block, labeled), message clamping, and prompt-injection guardrails; Bicep for
   the function app; and a runbook README including the hard-won gotchas (classic
   Y1 Linux has no Node 24 image, so the host never starts; OneDeploy `415` on
   Flex means use config-zip; secrets are named operator gates). Tests:
   `node --check`; Bicep compiles if the CLI is available (else documented).

8. **`examples/governed-transaction-saga/`** — a compact (~300-line + tests)
   sanitized distillation of the event-sourced governance core: an append-only
   event log with tenant/correlation/causation IDs and idempotency, a fold/apply
   state machine for a service transaction, complete-at-write receipts, and an
   audit walk that produces a chronological narrative plus a receipt-gap report.
   Pure Python stdlib with a pytest suite; all-new code written for the example,
   fictional scenario, tied in its README to the platform's HITL approval +
   governor features.

## Reliability hardening

Six merges under one theme: turn a way this platform — or an app it vendors —
could fail silently into something that fails loud. All are part of the v1.7
milestone.

- **Agent-loop canary.** `local-stack-smoke` checked containers and health
  endpoints but never proved an agent could finish a task. The new canary
  (`scripts/canary/`, wired into `.github/workflows/local-stack-smoke.yml`) files
  a real issue, wakes it, spawns the real vendored Hermes runtime, routes a model
  call through the model-router (real auth + tier dispatch), executes a real
  terminal tool call, and checks for a disposition comment before the issue
  closes — only the LLM reply is stubbed. Building it found and fixed six
  previously invisible stack-shape defects, headlined by **Hermes never being
  able to boot inside the AAF PaperClip image at all**: the `hermes-cli` build
  stage installed on `python:3.14` against a `python3.13` runtime, so every agent
  spawn died `ModuleNotFoundError` while every health check stayed green. See
  [`../local-development.md`](../local-development.md#agent-loop-canary-the-smoke-that-proves-agents-can-work).
- **Vendored-config schema guard.** A new `validate-vendored-config` CI job loads
  the pinned vendored source of each app (Honcho's real pydantic-settings model,
  an AST parse of Hermes's config parser, a version-pinned manifest for PaperClip)
  and validates every config key AAF ships against what that source actually
  reads. Its first run found **57 stale flat Honcho keys in `honcho.tf`** and
  **19 more in the mac-site compose file** (both pre-dating the 3.0.7 nested
  `MODEL_CONFIG` migration — a live deploy would have silently run every
  specialist on direct-OpenAI `gpt-5.4-mini`), plus an inert `HERMES_DB_PATH`
  variable the pinned Hermes build never reads. All fixed in the same PR. Design
  doc: [`../design/vendored-config-schema-guard.md`](../design/vendored-config-schema-guard.md).
- **Hard cost-envelope enforcement.** The v1.5 cost-governance layer moves from
  observe-only to enforceable behind `BUDGET_ENFORCE_MODE` (`warn` default /
  `downgrade` / `block`), now covering every router path including the native
  `/v1/messages` Anthropic transport — which now records spend at all (previously
  zero). Embeddings spend is budgeted too, in its own ledger bucket.
- **Provider-flexible embeddings.** `/v1/embeddings` gets a documented Azure AI
  Foundry deployment path ([`../walkthroughs/azure-foundry-embeddings.md`](../walkthroughs/azure-foundry-embeddings.md))
  and a load-bearing `openai/` LiteLLM provider-detection pin baked into the
  router, so forks don't rediscover the `400 unknown_model` failure mode against
  a Foundry endpoint.
- **Canonical user-peer identity.** `HONCHO_USER_PEER_ID` names the memory peer
  for the human principal, resolved identically — same default fallback — by
  every writer and reader: Terraform, compose, the memory-governor, and the
  Hermes helper scripts. Closes AAF's own seeds of the peer-fragmentation failure
  mode. [`../design/memory-system.md` §18](../design/memory-system.md#18-identity-the-canonical-user-peer).
- **Vendored incident-fix defaults.** Three fixes ported from the upstream
  private deployment's incident history: the generated Hermes config defaults to
  the router-compatible `chat_completions` + `api_key` shape instead of one that
  401s against fail-closed auth; the adapter build patch pins `--provider custom`
  in both the npm dist and the workspace source PaperClip loads at runtime; every
  agent template gets an explicit disposition protocol — exactly one terminal
  state per run.

## Upgrade notes

- **Migrations.** Apply `0009`, `0010`, and `0011` via the documented operator
  path. After `0009` lands, run the backfill sweep passes described in its
  migration header (set `CONTRADICTION_LOOKBACK_DAYS=0` for a one-off
  full-corpus pass) before relying on steady-state recency windows.
- **Flags stay off.** `MEMORY_DIGEST_ENABLED` and `ESCALATION_SLA_ENABLED` are
  seeded off; the inspector summary and the raw `/memory-digest` / `/escalation-sla`
  endpoints are read-only and safe to call for preview at any time. Flip the two
  flags when you want their sections folded into the daily `/digest` post. With
  both off, `/digest` is unchanged.
- **Escalation emitters.** The escalation SLA auditor reports an honest zero
  until the HITL approval seam emits `escalation_*` events at real volume; no
  action is required to adopt it early.
- **Security batch.** PR #97 changes no runtime defaults you must reconfigure,
  but note the fail-closed auth change: any service left with an *unconfigured*
  auth secret will now return `503` instead of serving open. Confirm each
  service's auth secret is set before deploying. The Key Vault and storage
  firewalls now default to `Deny`; populate the new allowlist variables for your
  environment.

## Addendum — v1.7 expansion packages

Written after the notes above merged (PR #105); this section extends them
without rewriting. Three expansion packages were cut for the v1.7 cycle. Two
items land with this addendum's own PR; the status of the other two packages is
reported honestly rather than pre-announced.

12. **Multi-tenant console demo** (`demos/tenant-console/`, expansion V3). A
    sanitized, static, read-only demo of the multi-tenant operator console: a
    tenant list (six fictional tenants — vertical, status, assigned playbook
    pack, monthly budget cap, spend-to-date with a %-used bar), a per-tenant
    detail drawer (assigned pack, a feature-flags panel with every flag **off**,
    budget/cost view with daily and per-run caps, roster, and a representative
    green/yellow/red fail-closed autonomy policy), and a playbook-packs view
    showing pack-to-tenant assignment. One self-contained `index.html` — inline
    CSS and vanilla JS, inline fixtures, zero external resources — renders
    straight from `file://` and is prominently labeled
    "DEMO — sample data, read-only, no live tenants"; every button is a visible
    no-op. The full platform console is operator-coupled (live DB, real budget
    ledger, real packs), so what ships here is deliberately its inspectable
    shape, not a wired port. Includes a rendered screenshot
    (`console-shot.png`) and a screenshot script following the existing
    `demos/forge-console-shot.mjs` pattern. Verified: `node --check` on the
    script, an external-resource grep returning zero off-box references, and a
    headless-browser render.

13. **Deployment experience** (expansion V3). Three additive layers on the
    established setup surfaces, no behavior removed:
    - `./forge --check` (alias `--preflight`), backed by a new
      `installer/preflight.py` (stdlib + `installer.core` only): prints a
      prerequisite table, a per-path readiness verdict (Azure / local Docker),
      and the operator-gate reference; exits `0` if any deploy path is ready,
      else `1`. Runs without the venv and makes no cloud calls — it reuses the
      same read-only local probes (`terraform version`, `az account show`,
      `docker info`) the console already performs.
    - Forge Console (`installer/static/index.html`): an
      "Operator gates — where you sign off" card that names each human-approval
      gate — subscription/billing, secrets-in-Key-Vault, environment-name
      confirmation, destroy-approval (`approve-destroy`), and CI/CD
      scaffold-apply (`scaffold-apply`) — plus advisory inline validation on the
      Configure fields mirroring the server-side regexes (the server stays the
      source of truth; buttons are never disabled client-side), and theming for
      the previously unstyled CI/CD setup panel. Still a single self-contained
      file with no external resources.
    - `AI-ASSISTED-SETUP.md`: a preconditions checklist, an
      "Operator gates / human sign-off required" subsection using the same gate
      names, and per-phase "how to know this step worked" verification signals.
    Verified: `py_compile` clean, `bash -n` on `forge`, `./forge --check` run
    end-to-end, `node --check` on the extracted inline scripts, and the
    installer suite green (83 passed).
