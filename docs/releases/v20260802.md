# v20260802 — cost governance becomes a loop

*First release under date-based versioning (`vYYYYMMDD`). The previous release was v1.8.2; the semver line ends there. A platform that ships when features are ready, not when a version number feels earned, should version by date.*

Six features, one arc: the platform's cost and behavior controls now cover **prevention → enforcement → detection → forensics**, and each layer feeds the next. This release also carries three flag-gated feature tracks merged 2026-07-22 — HITL approval wiring, the multi-tenant offline phases, and the voice-core track — documented in [Also in this release](#also-in-this-release--three-flag-gated-feature-tracks) below.

- **Prevention (config time):** the roster cost gate and the prompt replay gate fail a PR before an over-subscribed budget or a regressed agent prompt ever deploys.
- **Enforcement (request time):** circuit breakers and the scoped kill switch stop dispatch that shouldn't happen; the metadata fastpath removes LLM calls that never needed to happen.
- **Detection (minutes):** watchdog detectors alert on runaway loops, silent model degradation, and burn-rate pace.
- **Forensics (afterward):** the flight recorder holds the replayable trace that explains what any of the above did, and why.

## Model router

### Flight recorder + waste breakers

Every `/v1/chat/completions` and `/v1/messages` call lands in a bounded in-memory ring buffer (optional size-capped JSONL persistence): caller, model requested vs served, tokens, latency, cost estimate, outcome, breaker verdicts. Prompt/response text is redacted by default, enforced inside the recorder, so `FLIGHT_RECORDER_ENABLED` defaults on. Waste breakers (pure stdlib decision logic, same shape as `budget_enforcement.py`) detect identical-call repetition, per-caller retry storms, oversized prompts, and consecutive-failure streaks — observe-only by default, `block` mode env-gated. Inspect with `GET /debug/flight-recorder`. Design: [`docs/design/router-flight-recorder.md`](../design/router-flight-recorder.md).

### Fail-closed resilience pack

Three-state circuit breakers keyed per upstream **credential identity** (`api_base`+`api_key` hash — a revoked key 401s for every deployment it fronts, and ephemeral passthrough tiers keyed by name would never accumulate enough failures to trip). Narrow allowlist trip taxonomy: 401/403 auth, 429 quota, connection failures only — model-content errors and empty responses explicitly excluded, because a breaker that counts "the model returned an empty string" trips on healthy traffic. While OPEN: typed 503 (`UPSTREAM_BREAKER_OPEN`), upstream never invoked. `ROUTER_BREAKER_FAIL_CLOSED` (default on) also refuses *metered* fallback while the primary's breaker is open; free local Ollama tiers still serve. Plus a scoped kill switch (`paid_fallback` / `all_paid`): boot posture via env, runtime flips via `POST /debug/kill-switch` with actor and reason recorded to the flight recorder, typed 503 (`PAID_ACTIONS_DISABLED`) while engaged. Optional `ROUTER_ADMIN_API_KEY` separates "may call the router" from "may turn its spend controls off". Design: [`docs/design/router-resilience-pack.md`](../design/router-resilience-pack.md).

## Watchdog

### Agent ops alert pack

Three detectors, all riding the existing finding/lesson paths, all observe-only: **runaway run-loop** (per-issue re-run counts with a churn-ratio backstop), **silent model degradation** (served model vs an operator-declared `WATCHDOG_EXPECTED_MODELS` map), **spend burn-rate** (projects period-end spend from a dedicated 24-hour window — a short window makes an ordinary burst indistinguishable from a runaway when projected forward). Design: [`docs/design/watchdog-agent-ops-alerts.md`](../design/watchdog-agent-ops-alerts.md).

## CI gates

### Prompt replay gate — CI for prompts

Agent prompt changes are code changes nobody tests. On any PR touching `agents/profiles/`, the gate canonicalizes base and candidate prompt trees (`scripts/replay-gate/compose_prompt.py` — a validating canonicalizer, since AAF ships `.AGENTS.md` files verbatim minus frontmatter; it fails loudly where the deploy path would silently no-op), then runs eight contract fixtures against both and diffs: base-pass→candidate-fail is a REGRESSION and blocks; fail→pass is an IMPROVEMENT and is noted. Shipped fixtures pin the disposition protocol, scope guards, Security's critical-escalation carve-out, CostGuardian's read-only boundary, no hardcoded model names, no internal URLs, and per-agent token-budget ceilings. `--self-test` seeds a synthetic regression and proves the gate catches it before trusting any pass. Building the gate found a real defect: the `generalist` role had a full YAML contract and no governance prompt at all — fixed this release. Design (including the future live-replay-from-flight-recorder direction): [`docs/design/prompt-replay-gate.md`](../design/prompt-replay-gate.md).

### Roster cost gate — budget solvency at config time

AAF had no platform-wide budget cap and no per-agent ceilings — the runtime budget enforcer acts per model tier, and the watchdog's cap table covered 2 of 14 agents. Nothing summed the roster. Now every agent profile declares `daily_budget_usd` (schema-validated), the root compose file commits `PLATFORM_MONTHLY_BUDGET_USD`, and `scripts/roster-cost-gate.py` fails any PR where the 30-day ceiling projection exceeds the cap, printing sum, cap, delta, and top contributors. These are ceilings, not a forecast — the defect class is two config values nobody reconciles. Shipped roster: $183.00/mo against a $200.00 cap. Design: [`docs/design/roster-cost-gate.md`](../design/roster-cost-gate.md).

## PaperClip orchestrator

### Zero-LLM metadata fastpath (dark)

Platform-metadata questions on assigned issues — which model ran this, how long did it take, run provenance — are answered deterministically at run-execute time: conservative classifier, server-side comment (labeled as deterministic, so a reader knows no model ran), issue closed, run finalized. Zero LLM calls, zero terminal. The classifier is deliberately narrow: only unambiguous metadata questions qualify, because wrongly fastpathing a real task is far worse than wrongly LLM-ing a metadata question — porting it tightened a pattern the private original got wrong (a bare `billing` keyword that would have swallowed "update the billing model docs"). Applied as a build-time source patch on the pinned upstream, fail-loud on anchor drift, following the repo's existing patch conventions. `PAPERCLIP_METADATA_FASTPATH`, default **off**; when off the request path is byte-identical. Measure the saving with the flight recorder. Design: [`docs/design/paperclip-metadata-fastpath.md`](../design/paperclip-metadata-fastpath.md).

## Also in this release — three flag-gated feature tracks

### HITL approval seam — wired

The v1.5 action-approval seam ([`apps/paperclip/approval.mjs`](../../apps/paperclip/approval.mjs)) shipped fully tested but unwired; the v1.7 escalation-SLA auditor had no event emitter and reported an honest zero. Now: the auth-proxy gates an agent posting a comment (`POST /api/issues/*/comments`) as kind `outbound_message` before it reaches PaperClip — a gated action mints an `escalation_id`, emits `escalation_opened`, decides via the configured provider, emits `autonomy_decision` with latency, and returns 403 on deny. The governor gains `POST /escalation-event` as the single emit endpoint, and Terraform threads `GOVERNOR_BASE_URL`/`GOVERNOR_API_KEY` onto the paperclip container so the events actually land. Two deliberate error postures: the **gate fails closed** (deny on error), the **emit fails open** (lost telemetry never flips a decision). Inert by default — `APPROVAL_REQUIRED_KINDS` empty gates nothing; the comment route is byte-for-byte unchanged until an operator opts a kind in. 6 node + 6 pytest offline tests. Spec: [`docs/superpowers/specs/2026-07-22-hitl-approval-wiring-design.md`](../superpowers/specs/2026-07-22-hitl-approval-wiring-design.md).

### Multi-tenant — offline phases 1–5

The `experimental/multi-tenant/` reference design gained a deployable path and its offline enforcement cores:

1. **Deployable module** ([`infrastructure/modules/multi-tenant/`](../../infrastructure/modules/multi-tenant/)): control-plane + memory-store as ACA container apps — per-app managed identity, internal-only ingress, scale-to-zero — everything count-gated on `multi_tenant_enabled` (default false; zero new resources, no plan diff when off). Images added to `build-and-push.sh`; `control-plane-operator-key` seeded.
2. **Per-user identity**: `user_tokens.py` issues/verifies HS256 access tokens carrying `(user_id, tenant_id, role)` — stdlib-only, fail-closed (rejects alg-none/confusion, tamper, expiry, missing claims); memory-store `require_principal` derives all three from one verified token.
3. **RBAC**: monotonic role→scope table (viewer < member < operator < owner) and `require_scope()`, 403 when lacking; unknown role grants the empty set, import-time assert keeps roles and scopes in sync.
4. **Per-tenant daily budget cap**: in-memory ledger keyed `(tenant, day)`, off/warn/block modes matching the router's `BUDGET_ENFORCE_MODE` vocabulary, fail-closed default block, a blocked spend never recorded.
5. **Tenant onboarding**: `validate_contract` (exactly one owner, valid roles, positive budget) + `plan_provisioning` emitting ordered steps (create_tenant → set_budget → provision_workspace → create_user (owner first) → enable_pack), raising with every reason on an invalid contract.

37 offline tests across the four cores, all in CI. Live follow-ons: per-user RLS keying, persistent spend, executing the onboarding plan against live control-plane + Azure Search + Postgres.

### Voice track — offline core, phases 1–5

A greenfield [`services/voice-core/`](../../services/voice-core/): pure, offline-testable, no LLM client imported.

1. **Turn pipeline**: value types + Protocols, a two-state VAD with debounced end-of-speech + barge-in, the synchronous turn loop, a persona overlay, a fake STT/TTS provider — plus a Microsoft Voice Live adapter that is present and type-checked but **unverified** (raises until a live spike confirms the contract).
2. **Web session**: duplex-transport pump with a hard consent gate — no frame processed, nothing recorded until `grant_consent()`; revoke closes immediately; `purge_recording()` as the retention hook.
3. **Twilio surface**: fail-closed DTMF PIN gate (starts locked, N wrong attempts → permanent lockout), stdlib G.711 μ-law decode, Media Streams event parsing (malformed payload → silence, never crash).
4. **Discord surface**: RFC 3550 RTP parsing and a sequence tracker (in-order/duplicate/reordered/gap with 16-bit wraparound); Opus decode is an injected hook, native lib kept out of the offline core.
5. **Ops**: per-turn latency + cost attribution.

42 offline tests, wired into CI. Live follow-ons: WebSocket/WebRTC bridge + browser widget, a Twilio number + TwiML wire, the Discord voice gateway + libopus, and a verified STT/TTS provider.
